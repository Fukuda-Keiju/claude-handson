# テーマB 講師ガイド 統一版（人数・会場/オンラインに依存しない 1 本の台本）

本編 `theme-b-facilitator-guide.md` の代替案。**会場が 0 人でも 20 人でも、オンラインが 3 人でも 50 人でも、同じ原稿で進む**ことを最優先にした構成。
本編と違うのは「誰が手を動かすか」だけで、芯（情報の差 / 緑→赤→緑 / 投票と 4 分類 / 最後の 5 分）は同じ。

---

## 0. 設計の考え方（なぜこの形か）

本編は「会場 = 手を動かすテスター、Zoom = 仕様書を持つ設計者」と、**場所で役割を分けていた**。人数と場所が読めない今回、場所に依存する要素をすべて外す。

| 依存していたもの | 統一版での扱い |
|---|---|
| 会場の人数（zip・ユーザー・番号札） | **配布 zip なし、npm なし、Claude Code なし。** 参加者に必要なのはブラウザだけ |
| 会場 / Zoom で別チャット | **全員 Zoom に入る**（会場の人も自分の端末で。音声はミュート）。チャットは 1 本、投票も 1 本 |
| Zoom 視聴者 = 設計者役 | **設計者役（審査員）は開始時に希望者 2〜3 名を選ぶ。** 会場かオンラインかは問わない。仕様書は Zoom のダイレクトメッセージで渡す |
| 参加者が Claude Code でテストを生成 | **生成は講師のライブ 1 回だけ。** 参加者は生成を見て、出来たテストを自分のブラウザで実行する |
| 参加者が build / deploy | 講師だけ |
| UI テストを各自の Client Test Runner で実行 | **参加者が実行するのはサーバー側テストのみ**（ブラウザのタブ操作が要らない）。UI テストは講師が実行して画面共有で見せる |

参加者の「手を動かす」体験は **Run Test ボタンを押して、緑と赤を自分の画面で見る** に絞る。初学者でも 1 分で覚えられ、人数が増えても講師の負担が増えない。

**失うもの**: 参加者自身が AI にテストを書かせる体験。これは終了後の「自席で試す手順」（付録 A）で補う。

## 6. 未確認事項（木曜パイロットで確かめる）

- **同じテストの同時実行（2026-09-16 に確認済み）**: サーバー側テスト T1 を 3 本同時に投入したところ、エラーにはならず全部成功。ただし **同時には走らず 1 本ずつ順番に処理され、1 本あたり約 10 秒**（実行自体は 1 秒、残りは待ち行列とロールバック）。20 人が一斉に押すと最後の人は約 3 分待つ。対処: 「押したら結果が出るまで最大 3 分かかります。Pending や Running のまま待ってください」と先に言う。待ち時間は投票と予想チャットで埋める（22〜30 分と 35〜43 分に既に組み込み済み）。ユーザーが同じかどうかは関係ない。
- 会場の人がスマホの Zoom からでもチャットと投票に参加できるか。
- `atf10` への 2 回目の deploy（T4・T5 追加）で、既存の T1〜T3 の結果履歴が消えないか。

## 付録 A. 終了後に自席で試す手順（参加者に送る）

環境がある人向け。進行中は扱わない。

1. Node.js と `@servicenow/sdk` を入れ、`now-sdk auth --add` で自分の PDI を登録する。
2. `now-sdk init` で空のプロジェクトを作り、`theme-b/atf09/CLAUDE.md` をコピーする。
3. Claude Code を起動し、本編 2.3 のプロンプト①、次に②を実行する。
4. `npm run build` → `npm run deploy` → PDI の Tests 一覧から Run Test。
5. 詳しい解説は `atf-knowledge.md`。

## 0. まず用語（30 秒で）

| 用語 | ひとことで言うと |
|---|---|
| PDI | Personal Developer Instance。開発者が無料で使える自分専用の ServiceNow 環境 |
| スコープ / Scoped App | アプリの「名前空間」。このアプリで作った物にはすべて `x_2221398_handson_` が付く。他のアプリと混ざらないための仕切り |
| Fluent SDK | ServiceNow のテーブルや業務ルールを **TypeScript のコードで書いて** インスタンスに送り込む仕組み。GUI でポチポチ作る代わりにコードで作る |

| UI Page | 自分で HTML/JS を書いて作る画面。今回は React で作った |
| ATF | Automated Test Framework。ServiceNow 標準のテスト自動化。追加ライセンス不要 |
| build / deploy | `npm run build` = コードを ServiceNow が読める形に変換。`npm run deploy` = それを PDI に送って反映 |

## 1. 作ったアプリの全体像

「タスク管理」の小さなアプリ。3 つの部品でできている。

```
[Handson Task テーブル]  ← データの入れ物（Title / State / Due date / Completed at / Notes）
        ↑ 保存時に自動で動く
[Business Rule]           ← State が Done になったら Completed at に今の日時を入れる
        ↑ 画面から読み書き
[Task ボード (React UI Page)] ← Kanban ボード / 一覧 / 新規作成フォーム
        ↑ 動作を自動で確かめる
[ATF テスト 13 本 + スイート 1 本]
```

ナビゲーター（左メニュー）には「Claude Handson」というメニューが出て、
「Task ボード (React)」と「Handson Task 一覧」の 2 項目から開ける。

## 2. 設計（何を、なぜそう決めたか）

### 2-1. テーブル `x_2221398_handson_task`（ファイル: `src/fluent/tables/handson-task.now.ts`）

| フィールド | 型 | 決めたこと | なぜ |
|---|---|---|---|
| title | 文字列（100 文字） | 必須。表示名にする | タスク名がないと一覧で見分けられない |
| state | 選択肢 | Open / In Progress / Done。初期値 Open | Kanban の 3 列とそのまま対応させるため |
| due_date | 日付 | 任意 | 期限は無い場合もある |
| completed_at | 日時 | **読み取り専用** | 人が手で入れず、Business Rule が自動で入れるから |
| notes | 複数行テキスト | 任意 | メモ用 |

- `audit: true` にして変更履歴が残るようにした（誰がいつ変えたか追える）。
- デモ用レコードを 2 件、コードの中に定義した（`installMethod: 'demo'`）。deploy すると一緒に入る。
  - 注意: デモレコードは **Business Rule を通らずに** 入る。なので `state: 'done'` でも completed_at は自動では入らない。動作確認は手で状態を変えて行う（→ 5 章）。

### 2-2. Business Rule「Set completed_at on Handson Task」

- ファイル: 定義 `src/fluent/business-rules/set-completed-at.now.ts`、処理本体 `src/server/business-rules/set-completed-at.ts`
- 動くタイミング: **before**（保存の直前）、insert と update の両方
- ルール:
  1. state が `done` で completed_at が空 → 今の日時を入れる
  2. state が `done` 以外で completed_at が入っている → 空に戻す
- **なぜ before か**: 保存の直前に値を書き込めば、同じ 1 回の保存で一緒に保存される。after だと追加でもう 1 回更新が必要になり、無駄で、ルールが再発火する事故も起きやすい。
- **なぜ「戻す」処理もあるか**: Done → Open に戻したときに完了日時が残っていると嘘のデータになるため。

### 2-3. Task ボード（React UI Page）

- ファイル: 定義 `src/fluent/ui-pages/task-board.now.ts`、画面本体 `src/client/`
- URL: `https://dev192510.service-now.com/x_2221398_handson_task_board.do`
- 機能: Kanban ボード（カードを隣の列に移動）/ 件数タイル / ボード・一覧タブ / 新規作成フォーム / 未保存の変更があるときの確認モーダル
- **なぜ UI Page + React か**: SDK 4.x では React 製の画面を `UiPage` として配信できる。UI Builder を触らずにコードだけで画面まで完結できるため、Claude Code で生成しやすい。

### 2-4. ATF テスト（13 本）

- ファイル: `src/fluent/atf/`（テスト本体 `.now.ts`、ブラウザ側スクリプト `.script.js`、束ねる `handson-suite.now.ts`）
- 内訳:
  - サーバー側 4 本: Business Rule の「成立するとき」「成立しないとき」を insert と update の両方で確認
  - ナビゲーター 1 本: メニュー項目が見えるか
  - 画面 8 本: 一覧の絞り込み / 新規作成 / 未保存モーダル / Kanban 移動 / カード詳細 / タブ / タイル / ヘッダーから新規
- **なぜ肯定と否定を別々に書くか**: 「Done なら入る」だけ確かめても、「Open なのに入ってしまう」バグは見つからない。両方書くと初めて「ルール通り」と言える。
- **なぜ画面の成功メッセージを信用しないか**: 画面は「保存しました」と出しても DB に入っていないことがある。テストでは必ず DB（テーブル）を直接見て確認する。
- 詳しい ATF の知識は `docs/atf-knowledge.md` にまとめてある。

### 進め方（Claude Code の使い方）

1. 自分で「何を作るか」を文章で決める（2 章の表のレベルで十分）。
2. Claude Code に **仕様と制約** を渡す。制約の例: 「`now-sdk explain <topic>` で公式ドキュメントを先に読むこと」「`keys.ts` と `now.config.json` は触らないこと」「build / deploy / git は人（またはまとめ役）だけが実行する」。
3. 大きい作業は 2 つに分けて並列で作らせ、共通の「フィールド名の約束」だけ先に紙に書いて共有した（例: `src/client/types.ts`）。
4. まとめ役が 1 回だけ `npm run build` → `npm run deploy` → `now-sdk query` で反映を確認 → コミット。
   - **なぜ build を 1 人だけがやるか**: build すると `src/fluent/generated/keys.ts` に ID が自動追記される。複数人（複数エージェント）が同時に build するとこのファイルが衝突する。

## 6. つまずいた点と解決（昨日〜今日。手順書の「注意」欄の元ネタ）

| 症状 | 原因 | 解決 |
|---|---|---|
| PowerShell で `npm run build` が「スクリプトの実行が無効」で失敗 | Windows の実行ポリシーが npm の `.ps1` を止める | `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned` を 1 回実行。または `now-sdk.cmd` を直接呼ぶ |
| Claude Code から `now-sdk auth --add` ができない | 対話入力（パスワード）を Claude Code 経由では受け取れない | 自分のターミナルで実行する。Claude Code 上なら先頭に `!` を付けて `! now-sdk auth --add ...` |
| Business Rule で `gs.nowDateTime()` がエラー | スコープ付きアプリでは使えない API | `new GlideDateTime().getValue()` を使う |
| デモレコードに `state: 'done'` を書いたのに completed_at が空 | デモデータの投入は Business Rule を通らない | 仕様として理解。動作確認は手動操作か ATF で行う |
| React の UI Page が真っ白 | ServiceNow 側の古いライブラリ（prototype.js）が `Array.from` を壊し、フォーム部品が読み込み時に落ちる | `src/client/index.html` に `Array.from` を元に戻す小さなスクリプトを入れた |
| 画面の色（背景・ボタン）が消える | ServiceNow の CSS 変数 `--now-color_*` は「3,45,66」のような RGB の数字の組で、そのまま色として使えない | `rgb(var(--now-color_...))` で包む |
| ATF の画面テストが動かない | PDI の設定 `sn_atf.runner.enabled` / `sn_atf.schedule.enabled` が false | true に変更。UI テストには Client Test Runner（ブラウザのタブ）を開いておく必要がある |
| ATF で「保存」ボタンが見つからない | 画面幅で Save が直接ボタンになるか「More Actions」メニュー内になるかが変わる | テストで両方のパターンを扱う |

**教訓**: 型チェックが通っても画面は壊れていることがある。**必ず実物（スクリーンショットや実データ）で確認する**。

# よくある質問（テーマB ハンズオン）

## ATF について

**Q1. ATF は有料ですか。**
ServiceNow の標準機能です。追加ライセンスは要りません。
テストを「ステップの並び」で作り、ボタン 1 つで実行できます。

**Q2. なぜ最初はテストが実行できないインスタンスがあるのですか。**
`sn_atf.runner.enabled` が既定で false だからです。
本番で勝手にテストデータが作られないための安全装置です。今日の PDI では有効にしてあります。

**Q3. テストが作ったレコードはどうなりますか。**
各テストの最後に `recordDelete` で消し、ATF 自身もテスト終了時にロールバックします。
共有インスタンスでも汚れません。失敗して途中で止まった分だけ残ることがあります。

**Q4. 他の人のレコードと混ざりませんか。**
テストのタイトルに自分の番号を入れれば混ざりません。
ATF はロールバックするので、残ったレコードは放置して構いません。

**Q5. Client Test Runner のタブは閉じてよいですか。**
UI テストが動いている間は閉じないでください。閉じるとテストが止まります。
サーバー側だけのテストにはこのタブは要りません。

## 書き方・仕組み

**Q6. `.now.ts` と、ServiceNow 画面のテストはどういう関係ですか。**
`.now.ts` 1 ファイルが、ServiceNow のテスト 1 本（`sys_atf_test`）になります。
`npm run deploy` でインスタンスに送られ、画面の Tests 一覧に現れます。

**Q7. `$id` とは何ですか。**
テストとステップに 1 つずつ付ける名前で、インスタンス側の sys_id に対応します。
一度 deploy したら変えないでください。変えると別のテストとして作り直されます。

**Q8. ATF は React で作った画面をどうやって触るのですか。**
`atf.uiTestScript` で、TestingLibrary の `screen` / `user` を使って役割（role）と名前で要素を探します。
標準フォーム用の `atf.form` は React 画面には使えません。

**Q9. 要素の名前はどこから取るのですか。**
画面のソース（JSX）からの推測ではなく、実際の DOM から取ります。
今日は `CLAUDE.md` に要素名の一覧を書いてあるので、AI はそれを読んで書きます。

**Q10. 別スコープのアプリをテストできますか。**
できます。今日がまさにそれで、テストは `x_2221398_atfNN`、対象アプリは `x_2221398_todo` です。
テーブル名や画面の URL で対象を指すだけなので、アプリ側は触りません。

## 今日の進め方について

**Q11. なぜ全員が講師の PDI（共有インスタンス）を使うのですか。**
各自の PDI に欠陥アプリを入れると、スコープ名の縛りで失敗しやすいからです。
ATF はロールバックするので、共有でもデータは汚れません。

**Q12. なぜ仕様書を最初に配らないのですか。**
「プロダクトだけを見てテストを作ると何が起きるか」を体験してもらうためです。
仕様を知らずに作ったテストは、欠陥もそのまま正解として写し取ります。

**Q13. なぜ Run Test ボタンだけで、CLI を使わないのですか。**
覚えることを減らすためです。60 分では手数を 1 つに絞ります。
CLI（`now-sdk cicd testsuite run`）でも同じテストを実行でき、CI からも呼べます。

**Q14. Negative Test が緑になったら、何が起きているのですか。**
そのテストが「拒否される」ではなく「保存できる」を期待して書かれています。
AI が今のアプリの動きを正解として写した状態で、赤の 4 分類の②「テストの間違い」です。

**Q15. Claude Code に仕様書を渡すと何が変わりますか。**
「何が正しいか」の基準が画面から仕様に変わります。
仕様で禁止された操作が分かるので、Negative Test を書けるようになります。

**Q16. テストを消したのにインスタンスに残っています。**
ソースを消しただけでは消えません。`Now.del('sys_atf_test', '<sys_id>')` を書いて deploy します。
挙動が変わっただけなら、削除せずテストを直すほうが結果の履歴が繋がります。
